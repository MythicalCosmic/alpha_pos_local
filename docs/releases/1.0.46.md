# Alpha POS Desktop 1.0.46

This release adds Alpha Waiter, a responsive phone and tablet interface served
directly by the restaurant's local POS. Waiters open `/waiter/` from the till's
LAN address, sign in with their existing waiter account, start or resume a shift,
select a table, submit orders, follow kitchen readiness, and hand payment to the
cashier. The interface supports Uzbek, Russian, and English and can be added to a
phone home screen when the browser's secure-context rules permit installation.

The waiter interface follows the local venue policy dynamically. Optional
discount, direct-payment, split-payment, cancellation, and mark-ready actions
appear only when the authenticated waiter has the corresponding capability.
Order creation and other sensitive retries retain stable idempotency keys. Drafts
remain on the device during a temporary network interruption, while prices,
totals, order state, permissions, stock effects, and payment results remain
authoritative on the local backend.

The bundled API response now includes subtotal, discount amount, and applied
discount rows in waiter order detail. Delivery addresses reach the existing
order service, and cancellation reasons are validated and retained in audit
metadata. The release adds no database migration and changes no cloud service.

Install using the existing Windows account after checkout activity stops,
preferably after shift close. Preserve the `%LOCALAPPDATA%\AlphaPOS` data
directory and a current backup. After installation, confirm version 1.0.46,
open `http://<till-lan-ip>:8000/waiter/` from a phone on the same network, and
verify login, shift state, table selection, order submission, kitchen readiness,
and cashier payment handoff before wider waiter rollout.
