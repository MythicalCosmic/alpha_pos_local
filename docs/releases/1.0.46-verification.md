# Alpha POS 1.0.46 — release verification

Desktop 1.0.46 is published on the control server and GitHub. This release adds
the Alpha Waiter web interface to the restaurant's local POS. It does not require
a cloud backend deployment or database migration.

[Download AlphaPOS 1.0.46 Setup](https://control.78.111.91.113.nip.io/updates/installers/AlphaPOS-1.0.46-Setup.exe)
or use the [GitHub release](https://github.com/MythicalCosmic/alpha_pos_local/releases/tag/v1.0.46).

Install under the existing Windows account after checkout activity stops,
preferably after shift close, while preserving `%LOCALAPPDATA%\AlphaPOS` and a
current backup. From a phone on the restaurant Wi-Fi, open
`http://<till-lan-ip>:8000/waiter/`. A configured non-default POS port replaces
`8000`. The page works over LAN HTTP; home-screen PWA installation and offline
shell caching activate only where the browser treats the address as a secure
context.

## Included behavior

Alpha Waiter provides session login, explicit shift start and close, live floor
and table state, personal active/history lists, menu search and category filters,
hall/pickup/delivery carts, order editing, kitchen readiness, cashier payment
handoff, and policy-gated discount, cancellation, direct-payment, and split-payment
actions. It defaults to Uzbek and includes Russian and English.

The browser keeps drafts and stable command identities across uncertain network
retries. The local backend remains authoritative for prices, totals, stock,
permissions, order state, and payment. Waiter order detail now includes subtotal,
discount amount, and applied discounts; delivery addresses reach order creation;
validated cancellation reasons remain in audit metadata.

## Verification

- Frontend: 6 tests passed; TypeScript and the production Vite build passed;
  `npm audit` reported zero vulnerabilities across 207 dependencies.
- Backend: Django system check passed; 5 focused web-app integration tests passed.
  The preceding waiter/order regression run passed 118 tests with 2 PostgreSQL
  row-lock cases skipped on SQLite.
- Frozen Windows build: `SELFTEST OK` under Wine with disposable embedded
  PostgreSQL, migrations, backend bind, mock sync/fiscalization, and WebView import.
- Bundle: 453 shared core source files matched. All 32 waiter static/template files
  matched the source in both the frozen bundle and signed archive. No private
  configuration was present.
- Signed updates: the existing root stayed unchanged. Targets, snapshot, and
  timestamp advanced from version 6 to 7. The Windows TUF client verified the live
  signature chain, and a retained version-6 client advanced to version 7.
- Public artifacts: the complete installer and signed target downloads matched
  their advertised byte lengths and SHA-256 values. The target was fetched through
  eight bounded HTTPS ranges, reassembled in order, and checked against the hash
  authenticated by the TUF client.
- GitHub: the release asset is uploaded and its server-reported digest matches the
  locally built installer.

Native Windows GUI layout, a fresh restaurant installation, phone-browser visual
inspection, and physical restaurant peripherals were not available in this
session. The release must still be installed and canaried on the restaurant till
before all waiters begin using it.
