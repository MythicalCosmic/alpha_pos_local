# Alpha POS Desktop 1.0.45

This release preserves waiter attribution after cashier settlement, enforces
waiter permissions and feature settings, makes table claims and order retries
safe, and corrects stock deduction timing and rollback. It also fixes PostgreSQL
courier-assignment locks and protects waiter identity through synchronization.

Managers can select cashier collection or explicitly permitted waiter collection
in `GET/PUT /api/waiters/settings`. Waiter collection also requires `order.pay`
and an active collecting shift. Shift-required ordering is separately configurable.
Paid-order refunds remain manager operations. Existing permission assignments
and the enabled/disabled waiter setting are preserved.

Waiter clients must retain an `Idempotency-Key` for create, add-item, cancellation,
and discount commands across uncertain retries. Settings belong to the local
backend; changing cloud settings does not configure a restaurant terminal.
No new waiter frontend is included in this release.

Startup applies `base.0057_waiter_service_identity` and
`base.0058_waiter_policy_audit`, plus any earlier pending migrations. These add
nullable service identity and policy evidence without inventing historical
waiter attribution or rewriting sales, tenders, balances, or loyalty history.

Install using the existing Windows account after checkout activity stops,
preferably after shift close. Preserve the data directory and a current backup.
Smart POS 0.0.11 or newer is required. After installation, verify backend version
1.0.45, cash/card checkout, waiter-to-cashier handoff, and sync queue drain before
wider rollout. The restaurant installation and physical peripherals require
verification on Windows; publishing this release does not perform that upgrade.
